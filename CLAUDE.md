# Working in this repo (agent conventions)

A monorepo of ~36 independent research projects. No shared build, no shared virtualenv, no
top-level entry point. See `README.md` for what each project is.

## Before you commit

**Notebooks.** `nbstripout` must be installed in the clone or you will commit megabytes of
base64 output images:

```bash
pip install nbstripout && nbstripout --install --attributes .gitattributes
git check-attr filter -- <notebook>      # expect `nbstripout` in active projects
```

`.gitattributes` decides which notebooks are stripped. Notebooks whose **outputs are the
result** (evaluations, comparisons, visualisations, experiments, reports) and **every notebook
in an archived project** are deliberately exempt — their plots are the only surviving record.
Do not widen the stripping rules to "clean up" those.

**Never commit:**
- Derived datasets — `background_subtraction/data_*fps*/` are regenerated by
  `downsample_dataset.py` / `convert_to_bmp.py`.
- Training results, `runs/`, `results_*/`, capture batches. Check `.gitignore` first.
- Anything into `.gitattributes` without checking it resolves: `git check-attr filter -- <path>`.

**Storage rules.** Large binaries route to LFS automatically. Small text — YOLO label `.txt`,
metric `.csv`, `temporalROI.txt` — is **deliberately excluded** from LFS because it compresses
~10:1 in Git and LFS defeats delta compression. Do not "fix" those exclusions.

## Before you change a project

**Check its status in `README.md` first.** ARCHIVED projects are frozen records of finished
investigations. Do not refactor, reformat or modernise them; do not strip their notebook
outputs. If something in an archived project looks broken, it probably is — say so rather than
fixing it.

**Data is not in Git.** Datasets and training results live on the fileserver (`/mnt/pg-fs01`,
`/mnt/pg-fs02`). Paths appear in notebooks. If a path does not resolve, the data was moved or
removed — do not fabricate a substitute or silently switch datasets.

**Duplication is real and load-bearing.** Camera geometry exists in four places, `bbox_filter`
in three, `objectdetectionmetrics` in two. Before editing any of them, establish which copy
ships. The shipping copies are usually in `PG2_GW` or `algo_system_emulator`, not here.

## Conventions

- Each project owns its dependencies; there is no repo-wide `requirements.txt`.
- Match the surrounding style within a project — they were written years apart and differ.
- `background_subtraction/` is the best-documented project; follow its pattern when adding
  docs elsewhere (a `readme.md` stating purpose, inputs, outputs, status).
- Results and conclusions belong in `PG2.wiki`, not buried in notebook output.
